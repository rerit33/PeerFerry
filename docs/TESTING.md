# Проверки PeerFerry

Автоматические тесты используют отдельные временные профили, случайные порты и loopback; групповые ключи не записываются в репозиторий. Они не заменяют межкомпьютерную проверку VPN.

```powershell
dotnet test tests/PeerFerry.Tests -c Release --logger "console;verbosity=normal"
pwsh -File scripts/build.ps1
pwsh -File scripts/test-ui.ps1
pwsh -File scripts/test-update.ps1
```

Проверяются приглашения и повреждённый ввод; выбор адаптеров без перехода на невыбранную сеть; опасные Windows-пути; чужой ключ группы; запрет внешних трекеров и чужих метаданных; реальная передача 16 МиБ с SHA-256; сохранение частичной загрузки и перезапуск; раздача получателем после отключения исходного отправителя; два одновременных peer-соединения с лимитом скорости; вложенные/пустые файлы в папках; переключение доступных адресов, восстановление сети; пауза/продолжение/удаление без удаления исходника.

Встроенная визуальная проверка WPF (только отдельный тестовый профиль):

```powershell
dist/publish/PeerFerry.exe --data-dir .work/ui-profile --smoke-test .work/ui-evidence
```

Проверка поднимает три настоящих узла через loopback/TLS, публикует файлы и папку и сохраняет PNG двух вкладок, нижних панелей, трёх разделов настроек, приглашения и уменьшенного окна. Проверяются предпросмотр без запуска загрузки, очередь/пауза, кнопки продолжения, сохранение выделения при обновлении, поиск, сворачивание подробностей, независимые лимиты, валидация и сохранение копии настроек, ручной выбор адаптеров после переключения режимов. Тестовый режим использует только loopback и отдельный профиль; при отсутствии `--data-dir` профиль создаётся в каталоге результатов.

`scripts/test-ui.ps1 -Executable <полный путь к PeerFerry.exe>` запускает ту же проверку для собранного пакета. PNG и результаты остаются в игнорируемой `.work/`. В приглашении на тестовом PNG содержится временный ключ тестовой группы; рабочие профили не используются.

## Проверка с друзьями

1. Оба компьютера: один и тот же VPN, одинаковая версия приложения, соответствующие разрешения брандмауэра.
2. Выберите только ZeroTier. Добавьте друга по приглашению и передайте файл 10–100 МиБ. Сверьте SHA-256 через `Get-FileHash`.
3. Повторите с папкой с кириллицей, вложенными файлами и пустым файлом.
4. Передайте файл 5–20 ГиБ: замерьте скорость, RAM и CPU. Архитектура потоковая, но производительность такого объёма пока не измерена.
5. На середине загрузки отключите VPN, верните его и перезапустите получателя. Загрузка должна продолжиться, а итоговый хеш совпасть.
6. Включите ZeroTier и Radmin. Проверьте одну запись участника, затем отключение основного пути во время загрузки. Это ключевая проверка реального failover, которую loopback не доказывает.
7. Третий участник: скачивание при наличии нескольких источников. После полной загрузки у второго выключите исходного отправителя и скачайте с оставшегося.
8. Выберите только рабочий тестовый интерфейс, затем снимите все галочки в ручном режиме: сеть приложения должна остановиться без переключения на другие адаптеры.
9. Проверьте лимиты и очередь, закрытие в трей, полный выход, восстановление передач.
10. На будущем опубликованном релизе проверьте обновление через GitHub. Локальный `test-update.ps1` проверяет реальное скачивание пакета, замену и перезапуск без публикации тестовой версии.

При ошибке сохраните версию, выбранные адаптеры, текст из журнала (клик по строке состояния), описание шага и хеши файлов. Не отправляйте `settings.json`, `identity.pfx` или приглашение в публичные issues.
