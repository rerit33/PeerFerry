# Приложение закрывается до появления окна

Установщик и portable 0.2.1 содержат .NET 10 x64 вместе с Windows Desktop Runtime. Установка отдельного .NET не является первым шагом диагностики. Сам факт использования Windows 10 ещё не устанавливает причину сбоя: нужны номер сборки, архитектура, код завершения и события загрузчика.

1. Скачать [PeerFerry-Diagnostics.zip](https://github.com/rerit33/PeerFerry/releases/download/v0.2.2/PeerFerry-Diagnostics.zip), распаковать и запустить `PeerFerry-Diagnostics.cmd` без прав администратора.
2. Если PeerFerry не установлен, выбрать `PeerFerry.exe` из распакованной portable-версии. Для установленного приложения путь определяется автоматически.
3. Дождаться итогового `PeerFerry-Diagnostics-ДАТА.zip` рядом со сборщиком и приложить его к сообщению о проблеме.

Сборщик запускается стандартным Windows PowerShell 5.1 и не зависит от установленного .NET SDK. Он включает трассировку загрузчика только для своего дочернего процесса, запускает встроенную проверку интерфейса в отдельном временном профиле и собирает связанные события Application, Code Integrity и Defender. Если проверка зависнет, завершается только созданный диагностический экземпляр. Проверка не регистрирует обработчик ссылок и не меняет рабочий профиль. Настройки, сертификат, секрет группы, снимки окон и пользовательские файлы не включаются в отчёт; приглашения в текстовых журналах скрываются.

Сборщик проверен на Windows 11 в Windows PowerShell 5.1: успешный запуск приложения и отказ запуска некорректного EXE. Отчёт с затронутого компьютера Windows 10 также успешно получен.

## Известный сбой 0.2.1: неполная поддержка CET

Отчёт от 6 ноября 2026 года показывает Windows 10 Pro 20H2 x64, build 19042.1526, и аварийное завершение CoreCLR 10.0.14 с кодом `0x80131506`. В `stderr.txt` указано: `Your Windows doesn't fully support CET. Please install all available Windows updates.` Приложение завершается до выполнения управляемого кода и создания интерфейса.

В 0.2.2 в проект приложения добавлено `<CETCompat>false</CETCompat>` — [документированный Microsoft способ отключить CET для исполняемого файла](https://learn.microsoft.com/en-us/dotnet/core/compatibility/interop/9.0/cet-support). Это убирает автоматическое включение аппаратной защиты теневого стека для процесса PeerFerry на всех версиях Windows; системная политика защиты не меняется. ASLR и DEP остаются включены. Отдельная проверка PE-заголовка при сборке и в CI не позволяет незаметно вернуть CET-флаг.

Если 0.2.1 не запускается, обновление из её интерфейса недоступно: установите 0.2.2 поверх старой версии либо распакуйте весь новый portable-архив в отдельную папку. Рабочий профиль находится отдельно от файлов программы. Успешный запуск на исходном компьютере с Windows 10 ещё ожидает проверки; это исправление устраняет установленный барьер CET, но не является подтверждением совместимости со всеми старыми сборками Windows.

В сборщике 0.2.2 системные события сохраняются с префиксом `events-`: имя `Application.txt` больше не перезаписывает `application.txt` с данными приложения на файловой системе Windows.
