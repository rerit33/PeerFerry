# Приложение закрывается до появления окна

Установщик и portable 0.2.1 содержат .NET 10 x64 вместе с Windows Desktop Runtime. Установка отдельного .NET не является первым шагом диагностики. Сам факт использования Windows 10 ещё не устанавливает причину сбоя: нужны номер сборки, архитектура, код завершения и события загрузчика.

1. Скачать [PeerFerry-Diagnostics.zip](https://github.com/rerit33/PeerFerry/releases/download/v0.2.1/PeerFerry-Diagnostics.zip), распаковать и запустить `PeerFerry-Diagnostics.cmd` без прав администратора.
2. Если PeerFerry не установлен, выбрать `PeerFerry.exe` из распакованной portable-версии. Для установленного приложения путь определяется автоматически.
3. Дождаться итогового `PeerFerry-Diagnostics-ДАТА.zip` рядом со сборщиком и приложить его к сообщению о проблеме.

Сборщик запускается стандартным Windows PowerShell 5.1 и не зависит от установленного .NET SDK. Он включает трассировку загрузчика только для своего дочернего процесса, запускает встроенную проверку интерфейса в отдельном временном профиле и собирает связанные события Application, Code Integrity и Defender. Если проверка зависнет, завершается только созданный диагностический экземпляр. Проверка не регистрирует обработчик ссылок и не меняет рабочий профиль. Настройки, сертификат, секрет группы, снимки окон и пользовательские файлы не включаются в отчёт; приглашения в текстовых журналах скрываются.

Сборщик проверен на Windows 11 в Windows PowerShell 5.1: успешный запуск приложения и отказ запуска некорректного EXE. Это подтверждает работу сборщика, но не исправление сообщённого сбоя Windows 10. Причина пока ожидает отчёта с затронутого компьютера.
